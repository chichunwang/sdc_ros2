# 05｜手動執行各版本（2026-11-18）

這份說明怎麼自己跑出每一個版本的結果。所有命令都在 Ubuntu 主機的 `midterm02/` 目錄下執行。
如果出現 `permission denied ... docker.sock`，在命令前面加 `sg docker -c '…'`（或重新登入讓 docker 群組生效）。

## 一張圖看懂版本之間的關係

```text
                ┌─────────────── E 系列（gslam：SIFT＋LoGeR ICP＋閉環＋SIFT BA）
                │   E21：Track1 用；Track2 尺度發散（不要用）
                │   E27：E21 修正版（相機高度尺度＋一致閉環）──┐ 提供：相機校正、閉環幀對、SIFT 特徵（BA 輸入）
                │                                              │
影像＋LoGeR ────┤                                              ▼
                └─── D 系列（DROID-SLAM 稠密光流）── D8 ──► P1（反向重訪約束）──► F1（全解析度 SIFT BA）
                      D2：Track1 最佳（0.068）        Track2 1.466   Track2 0.457        Track2 0.254（目前最佳）
```

- **E 系列**：自己寫的 gslam（`vslam/`），參數在 `vslam/gslam/params.py` 的 `EXPERIMENTS`。
- **D 系列**：DROID-SLAM，參數在 `scripts/run_droid.py` 的 `EXPERIMENTS`。需要一個 E run 提供相機校正（`--calib-from`）；D7 以上還用它的閉環。
- **P1、F1**：後處理，輸入是前一步的 run 目錄，輸出新的 run 目錄。

每一步都會在 `outputs/run/` 建一個新目錄（`track0X_full_YYMMDDHHmm`），結尾印出 `run: …` 與 `submission check: OK`。
提交檔是該目錄裡的 `result_1.csv`（Track1）或 `result_2.csv`（Track2）。

## 環境（第一次或重開機後）

```bash
./scripts/dev.sh up        # 啟動 gslam 容器（E 系列、P1、F1 用）
./scripts/dev.sh test      # 單元測試，確認環境正常
```

DROID 容器（D 系列）是一次性容器，`docker/droid/run.sh` 每次自動啟動，不用另外 up。

## 1. E 系列（gslam）

```bash
./scripts/dev.sh slam --track 02 --experiment E27_selfcalib_height
```

- `slam` 一定會開 RViz（看即時軌跡與地圖）。不想開 RViz、在背景跑：
  `./scripts/dev.sh exec python vslam/run_slam.py --track 02 --experiment E27_selfcalib_height`
- 換版本：把 `--experiment` 換成 `params.py` 裡 `EXPERIMENTS` 的任一名稱（例如 Track1 的 `E21_selfcalib`）。
- 只跑前 N 幀測試：加 `--frames 300`（產生 `track0X_test_…`）。
- 時間：Track2 約 55 分鐘（前端約 15 分鐘，BA 約 40 分鐘）；Track1 較短。

## 2. D 系列（DROID）

```bash
docker/droid/run.sh python3 scripts/run_droid.py --experiment D8_droid_selfcalib_depth_hnorm_loops_pgo \
    --track 02 --buffer 2560 --calib-from outputs/run/<E run>
```

- `--calib-from`：E run 的目錄（讀它的相機自校正結果與閉環候選）。目前的 Track2 D8 用的是 E21 `track02_full_2611171739`；用 E27 `track02_full_2611172248` 也可以（同樣的校正來源，閉環多 3 個起終點的）。
- `--buffer 2560`：Track2 的 keyframe 超過預設 1024，一定要加；Track1 不用。
- 換版本：`--experiment` 換成 `run_droid.py` 的 `EXPERIMENTS` 名稱，例如 `D2_droid_selfcalib`（Track1 最佳）、`D6_droid_selfcalib_depth_hnorm`。
- 時間：Track2 約 10 分鐘；Track1 約 3 分鐘。

## 3. P1（反向重訪約束）

```bash
./scripts/dev.sh exec python scripts/opposite_pgo.py --from outputs/run/<D8 run>
```

- 輸入必須是 D8（需要它的 `debug/loger_height.csv` 與 `debug/loop_measurements.csv`）。
- Track1 沒有反向重訪，結果與 D8 相同（只是讓 F1 有輸入可用）。
- 驗證用：加 `--holdout` 只用一半配對當約束，產生 `track0X_test_…`，再用
  `./scripts/dev.sh exec python outputs/cache/dev63_p1_eval.py outputs/run/<test run>` 看留出配對的殘差。
- 時間：約 3 分鐘。

## 4. F1（DROID＋全解析度 SIFT BA）

```bash
./scripts/dev.sh exec python scripts/droid_ba.py --from outputs/run/<P1 run> --ba-input outputs/run/<E run>
```

- `--ba-input`：有 `debug/bundle_input.npz` 的 E run（SIFT 特徵與匹配）。Track2 用 E27 `track02_full_2611172248`，Track1 用 E21 `track01_full_2611161931`。
- BA 參數預設取自 `E27_selfcalib_height`（可用 `--experiment` 換）。
- 時間：Track2 約 10 分鐘；Track1 約 1 分鐘。

## 從零重現目前的 Track2 最佳（F1，Public 0.254）

```bash
./scripts/dev.sh slam --track 02 --experiment E27_selfcalib_height                          # → <E27>
docker/droid/run.sh python3 scripts/run_droid.py --experiment D8_droid_selfcalib_depth_hnorm_loops_pgo \
    --track 02 --buffer 2560 --calib-from outputs/run/<E27>                                 # → <D8>
./scripts/dev.sh exec python scripts/opposite_pgo.py --from outputs/run/<D8>                # → <P1>
./scripts/dev.sh exec python scripts/droid_ba.py --from outputs/run/<P1> --ba-input outputs/run/<E27>   # → <F1>
```

注意：目前評分的 F1（`track02_full_2611172344`）的 D8 用的是 E21 的校正與閉環（`--calib-from outputs/run/track02_full_2611171739`）。
用 E27 當來源時多 3 個起終點閉環，結果會有小差異，要再提交一次確認。

## 跑完之後

1. 看結尾的 `submission check: OK`；也可以手動檢查：
   `./scripts/dev.sh exec python scripts/check_submission.py outputs/run/<run>/result_2.csv data/data_VSLAM-T2/Track2/data/sample_submission.csv`
2. 圖表在 `outputs/run/<run>/analysis/`（俯視軌跡等）。
3. 自我一致性比較（Track2，無 GT）：
   `docker/droid/run.sh python3 outputs/cache/dev64_compare.py 名稱A=outputs/run/<runA> 名稱B=outputs/run/<runB>`
4. Track1 的 IMU 一致性（越小越好）：
   `./scripts/dev.sh exec python outputs/cache/dev20_check.py outputs/run/<run>/result_1.csv`
5. 上傳 Kaggle 後把分數告訴我，我記到該 run 的 `test_info.json`（`public_score`、`reported_by`、`reported_at`）。

## 常見問題

| 狀況 | 處理 |
| --- | --- |
| `permission denied … docker.sock` | 命令前加 `sg docker -c '…'` |
| DROID `IndexError`（index 1024） | Track2 忘了加 `--buffer 2560` |
| `--calib-from` 錯誤 | 指向 E run 的目錄，不是檔案 |
| RViz 沒畫面 | `./scripts/dev.sh rviz`（重啟 RViz 與 bridge）；只有 E 系列會串流到 RViz |
| 想停掉 RViz | `./scripts/dev.sh rviz-stop` |
