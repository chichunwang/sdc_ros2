## 首建當時的 sudo 阻塞與後續解除（歷史）

**後續更新：** 2026-10-17 已觀察到 GPU 容器使用 `nvidia.com/gpu=all` 的 CDI 裝置，並實跑 `scripts/dev.sh cuda-check` 通過：RTX 5060、compute capability 12.0、4096 個結果正確。證據在 `outputs/runs/cuda_runtime_20261017_79psai_k/` 的 `cuda_check.log`／`validation.json`。本次未再執行主機安裝；下文保留首建時的阻塞紀錄。該次 runtime 檢查通過時，GPU NDT 尚未整合；之後 NDT 與新版 robust ICP 都已整合，見上述後續文件。

首建當時主機沒有 NVIDIA Container Toolkit，非互動 sudo 檢查顯示需要使用者密碼。因此尚未安裝主機套件、尚未產生 NVIDIA CDI 裝置規格。

`cuda-check` 在無 GPU 診斷模式下按預期失敗，錯誤保存在 `cuda_check_without_gpu.log`；這不是 GPU 執行成功。一般 `up` 的前置檢查會明確報缺少 CDI，不會默默降級成 CPU 模式。

在 Ubuntu 主機執行：

```bash
cd /home/ricky/sdc_ros2/midterm01_gpu
sudo bash scripts/setup_host_gpu.sh
bash scripts/dev.sh up
bash scripts/dev.sh cuda-check
```

安裝腳本只設定 NVIDIA 官方套件來源、安裝 Toolkit base 與產生原生 CDI 規格，不修改 Docker daemon 設定、不重啟 Docker。`up` 會依 GPU overlay 重建本 GPU project 的容器，workspace／outputs 都保留；原 CPU project 不在操作範圍。

上述步驟之後已保存真實 `cuda-check` PASS 證據；本機現在不需因這段歷史紀錄重新安裝 Toolkit。移機或 CDI 遺失才依 GPU README 診斷。
