# CUDA NDT 整合與前 50 幀實測（2026-10-17）

`midterm01_gpu` 現在預設使用 **CUDA NDT D2D／DIRECT7**，已在 RTX 5060、CUDA 12.8、PCL 1.12.1、ROS 2 Humble 建置並實跑兩條 Track 的前 50 幀。原 `midterm01` 的程式、建置與輸出保留；其 CPU localization 程序 PID 13216 在本次完成檢查時持續執行。

資料仍唯讀共用 `../midterm01/data`，沒有複製原始資料集。所有新結果位於本目錄的 outputs。此版本尚未做完整 Track／Kaggle 精度驗證，不是已確認的最佳提交版本。

## 實作範圍與來源

- `cuda_ndt_backend` 以 [fast_gicp](https://github.com/koide3/fast_gicp) commit `0e7ec1441c99f7be453db2ea216d5de029387417` 為來源，固定 archive SHA256，保留 BSD-3-Clause 授權。使用 upstream 的 CUDA NDT 與 LM 最佳化，並非自行發明新的 NDT。
- 本專案新增 CUDA 12.8／`sm_120` 的 CMake／ROS 2 包裝；只建置 NDT 需要的來源，不加入未使用的 VGICP／cuBLAS。新版 CCCL 的 Thrust namespace 相容性修正保存在 CMake，首次建置需網路下載固定來源。
- 新增 `registration_backend=cuda_ndt`（預設）與明確指定的 `pcl_ndt` 比較模式。CUDA 初始化或執行錯誤直接退出，不會轉為 CPU 後端。一般配準未收斂時仍保留上一個 pose，並計數。
- GPU 執行 voxel 統計、對應點／voxel 搜尋與 cost／gradient／Hessian 大量點運算；6×6 LM 解算、讀檔、濾波、裁切、PCL fitness、顏色點雲處理及 ROS 發布仍在 CPU。
- CUDA target 平移到 resolution 整數倍的局部原點，初值同步平移，結果再轉回 map。這避免 float voxel 共變異數在數千公尺座標的消去誤差；不改 source→map 定義，不重套初始矩陣或外參。零／非有限 Hessian 的結果不視為成功。
- GPU 副本修正既有 Boost path 的絕對快取路徑拼接問題，明確使用 outputs 的衍生快取，並捕捉寫入錯誤；原 CPU 副本未改。
- 新增 `timings.csv` 與 `scripts/benchmark.py`，保存分段耗時、參數、frame 對應、版本、程式／來源 SHA256、GPU 使用取樣、原始矩陣及輸出檢查。

## 固定設定與測量方式

前相機 raw_ply、`ply_scale=3.0`、map voxel 1.0、input voxel 0.3、submap 半寬 100／半高 30、NDT resolution 8.0、最多 30 iterations。CPU 保留 step 0.8／epsilon 0.05；CUDA 使用 LM、translation epsilon 0.01／rotation epsilon 0.002。CUDA 與 PCL 的目標函數、voxel／鄰域及收斂語義不同，這些不是數值等價的演算法設定。

所有比較不開 RViz、不讀 bag、`keep_alive=false`，每次使用唯一 run，取 timestamp 排序的前 50 幀。下面總耗時包含 Docker exec、ROS 啟動、地圖初始化與所有幀，不含建置。測試依序執行；原 CPU 完整 Track 工作仍在另一個容器背景執行，沒有進行獨占硬體或統計重複試驗。

`ndt_ms` 包含 input／submap 設定、傳輸、target tree／voxel 建立、配準與 CUDA 同步；CPU fitness 另計。`publish_ms` 包含顏色點雲濾波、發布與 pose 寫入。frame 總和不含 map 初始化、ROS 啟動、逐幀 spin 與記錄等外圍成本。

## 由原始地圖初始化的結果

| Track | 後端／版本 | 總耗時 s | 地圖初始化 s | 50 幀處理 s | NDT 總和 s | 輸出／回退 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 1 | 原 CPU R0（歷史首跑） | 322.519 | 未分段 | 未分段 | 未分段 | 50／0 |
| 1 | CPU PCL NDT Release | 84.035 | 76.545 | 6.786 | 2.545 | 50／0 |
| 1 | CUDA NDT D2D Release | 83.622 | 77.759 | 4.864 | 0.610 | 50／0 |
| 2 | 原 CPU R0（歷史首跑） | 118.509 | 未分段 | 未分段 | 未分段 | 50／0 |
| 2 | CPU PCL NDT Release | 7.931 | 4.092 | 3.139 | 1.041 | 50／0 |
| 2 | CUDA NDT D2D Release | 7.344 | 4.103 | 2.311 | 0.240 | 50／0 |

CPU Release 的兩條 Track `result.txt` 與原 R0 **逐 byte 相同**。因此不能把原先約五分鐘縮短至八十多秒的全部改善歸因於 GPU。以本次設定，NDT 階段時間約降為原 CPU Release 的四分之一；演算法、收斂路徑與 submap 可能不同，這不是相同 kernel 的純硬體速度比較。

Track1 的 ASCII 原始 map 有 59,531,846 點，載入／降採樣約 77 秒，已成為主要啟動成本；GPU 無法消除這段現有 CPU 讀檔流程。Track2 原始 map 為 binary，初始化約 4 秒。

Track1 CUDA D2D 當輪同時產生約 5.7 MiB、496,909 點的衍生 map 快取，當輪 `map_cache_hit_at_start=false`，仍讀取完整原始 map；另三個 Release 原始地圖比較沒有啟用快取。

## 已命中同一衍生快取的重複試跑

| Track1 後端 | 總耗時 s | 地圖初始化 s | NDT 總和 s | 輸出／回退 |
| --- | ---: | ---: | ---: | --- |
| CPU PCL NDT Release | 7.255 | 0.023 | 2.530 | 50／0 |
| CUDA NDT D2D Release | 5.895 | 0.024 | 0.587 | 50／0 |

這兩列使用相同的 Track1／leaf=1.0／原始 map SHA256 快取，預設 benchmark 並不啟用快取。原始 map SHA256 為 `2b30d4f469b8b792aaf37aeb7c8578023d4b89ed75c77e9edf17618b29f6e57a`；cache sidecar 核對 Track、map 來源、SHA256 與 leaf，不符或缺少即拒絕沿用。啟用快取時，benchmark 的 SHA256 前置核對不含在 ROS 程序總時間內。

快取是 outputs 中衍生的下採樣資料，不是另一份原始資料集。不可把命中快取的 5.9 秒對比原先未快取的 322.5 秒，宣稱為 GPU 加速倍數。

## 輸出品質的實測範圍

兩條 Track 的 CUDA D2D 結果均為 50 行、每行 12 個有限數值，旋轉 det 接近 1、正交誤差小於 `1e-6`，未發生配準回退。但與 CPU R0 的軌跡有明顯差異：

| 診斷 | Track1 | Track2 |
| --- | ---: | ---: |
| 相對 CPU R0 平移差異 RMS m | 4.803 | 7.807 |
| 相對 CPU R0 最大平移差異 m | 5.664 | 8.791 |
| CUDA 最大相鄰平移 m | 2.074 | 2.084 |
| CPU R0 最大相鄰平移 m | 0.796 | 0.262 |

上述是兩個估計器的差異，**不是 ground truth 誤差或正式 ATE**。CUDA 的局部跳動較大，需要後續逐幀疊圖、motion／品質門檻及正式資料評分檢查。沒有 Kaggle 分數，不能宣稱 CUDA 精度較好、等同原 CPU 或超過 baseline。

整合過程測試 P2D 時，未平移全域座標的版本曾有約 40 m 偏差；加入局部原點後仍出現單步 yaw 約 79° 的變化。D2D 在 Track1 的同項診斷降至約 7°，因此最後預設選擇 D2D。原始試驗與失敗快取測試都保留，不列為最終品質通過依據。

## 驗證與重現

- `cuda_ndt_smoke` 已知非零 source→target 變換：CUDA 配準收斂，未重套初值。
- `scripts/check_cuda_contract.py` 使用獨立合成資料，檢查 P2D／D2D 在數千公尺原點的矩陣方向、無對應點回退與預設 CUDA D2D 路徑。這只是數學／程式契約檢查，不替代真實資料精度驗證。
- `CUDA_VISIBLE_DEVICES=-1` 負向測試在讀 map／開啟 result 前失敗，沒有轉成 CPU。
- Release 建置、launch 入口、兩條 Track 的 50 幀實跑、原環境 tracked diff 保留及唯讀掛載均有記錄。

一般前 50 幀試跑，在 Ubuntu 主機執行：

```bash
cd /home/ricky/sdc_ros2/midterm01_gpu
python3 scripts/benchmark.py --track 1 --frames 50
python3 scripts/benchmark.py --track 2 --frames 50
# 同一 Release 程式的 CPU 比較
python3 scripts/benchmark.py --track 1 --frames 50 --backend pcl_ndt
```

修改 C++ 後先 `bash scripts/dev.sh build-workspace`。後續如需 P2D／不同 resolution 的實驗，明確傳入 `--cuda-mode P2D`／`--resolution`；不要默認既有參數已校準。
