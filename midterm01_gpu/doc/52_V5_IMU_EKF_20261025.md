第一張 PLY timestamp `1727239790258245070` 與第一張 front camera 的 **bag arrival timestamp** 相同；該影像的 acquisition header 是 `1727239790226594548`。因此兩個 clock 不是同一個值。舊實作拿相鄰 PLY bag arrival 間隔計算視覺速度，修正後的 clock 對齊與數值比較見 doc55。此表中的 bag/header latency 統計仍是原始輸入稽核結果；它們不是硬體同步精度證明。

**目前契約：**PLY 檔名的 bag timestamp 是資料 availability cutoff；frame 的定位／速度 `dt` 使用同一 bag 對應的 camera header acquisition time；IMU 積分使用 `/imu/data` 的 header acquisition time。每筆 IMU 必須同時滿足 bag arrival ≤ 目前 PLY arrival，以及 IMU header ≤ 目前 camera header。已抵達但 header 在目前影像之後的 IMU 暫存到後續 frame；已錯過該影像擷取時間才抵達的資料不會回頭修改任何已輸出的 pose。IMU 在已知樣本之間採 forward zero-order hold，不用未來樣本插值。第 0 幀把初始 pose 作為當前 camera acquisition 時刻的 anchor，不從 bag 開始處積分舊位移。輸出 timestamp 和 frame 順序仍保留原始 PLY 的整數 bag timestamp。所有 timestamp 先以整數 ns 相減，再轉成秒。逐步規則與首段對照見[doc55](55_V5_STARTUP_CLOCK_FIX_20261025.md)。

[ROS Humble Imu 定義](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/Imu.msg)指定角速度 rad/s、加速度 m/s²；全零 covariance 是未知，首元素 −1 表示欄位不存在。[REP145 原始規範](https://github.com/ros-infrastructure/rep/blob/master/rep-0145.rst)以 specific force 描述加速度；水平靜止且 sensor +Z 朝上時約為 +g。v5 按此模型處理，raw norm 不能獨立證明軸向、靜止、重力或 bias。欄位不存在、frame 不符、非有限值或 IMU stale 時明確停止，不靜默切換 predictor。

## 模型、座標與殘差

nominal state 是 IMU 原點的 `(p_map, v_map, R_map_imu, ba_imu, bg_imu)`。15 維 error 的固定順序與左擾動定義：

```text
δx = [δp_map(3), δv_map(3), δθ_map(3), δba_imu(3), δbg_imu(3)]
R_true = Exp(δθ_map) R_nominal
```

全域角度誤差與 injection/reset 原理參考 [Solà §7](https://arxiv.org/html/1711.02508v1#S7)。本專案採 rotation matrix、固定重力的 15 維版本，沒有估計 gravity state。實作 dynamics：

```text
ω = angular_velocity − bg
f = linear_acceleration − ba
R_mid = R Exp(ω dt/2)
a_map = R_mid f + g_map
p_next = p + v dt + 0.5 a_map dt²
v_next = v + a_map dt
R_next = R Exp(ω dt)
```

IMU native frame 保留到 dynamics，再以 `R_map_imu` 轉到 map；不把不同原點的加速度直接當 camera 加速度。`g_map=[0,0,-9.80665] m/s²` 暫假設 map +Z 向上。初速估計為零、std 10 m/s，表示未知初速的初始估計，不表示車輛靜止。bias 初值為零，透過多次地圖量測與狀態 cross covariance 更新。

連續 error model 的非零 blocks：`F_pv=I`、`F_vθ=−[R_mid f]×`、`F_vba=−R_mid`、`F_θbg=−R_mid`。離散 transition 採二階 `I+Fdt+F²dt²/2`，noise integral 採三點正權 Gauss quadrature；每段拆到不超過 10 ms。這是數值近似，有對 Van Loan matrix exponential 與 nonlinear finite difference 的檢查；不宣稱 exact continuous discretization。noise 及 bias random walk 進 covariance，不向 nominal state 加隨機亂數。

外參契約：

```text
E = T_ply_imu
p_ply = R_ply_imu p_imu + t_ply_imu
T_map_imu = T_map_ply E
T_map_ply = T_map_imu inv(E)
```

`t_ply_imu` 是 IMU 原點在**公尺制 PLY FLU** 的位置。reconstruction scale `s` 只用在 `q=s R_map_ply p_raw+t_map_ply`，不乘到 IMU、重力、速度或外參平移。保留 IMU 原點 state，再轉回 camera pose，自然包含 lever arm；不對 noisy gyro 差分去硬扣 camera 向心／切向加速度。

量測先轉成 `Z_imu=T_registration_ply E`：

```text
r_p = p_Zimu − p_prediction_imu
r_R = Log(R_Zimu R_prediction_imu.T)
H = [I 0 0 0 0; 0 0 I 0 0]
S = H P H.T + V
NIS = r.T solve(S,r)
```

registration std 定義於 PLY 原點、map 平移與左旋轉誤差。轉到 IMU 原點時，用 `J=[I, −[R_ply t_ply_imu]×; 0,I]` 傳播 `V=J diag(std²) J.T`，保留 lever arm 的位置／姿態相關性。沒有把 robust registration Hessian inverse 當已校正量測 covariance。

先遵守 doc50 registration gate：收斂、coverage、幾何可觀測及合法 pose/scale。**首筆**通過的 registration 建立 pose anchor，重設 pose covariance/cross terms，恢復初始速度／bias 設定及其不確定度；不讓 noisy initial guess 的 NIS 擋住第一個 anchor，也不把初始化跳變除以 dt 當車速。後續檢查 6 DoF chi-square NIS（probability 0.999，門檻約 22.46），再作 Kalman update、Joseph covariance update 和 global-left SO(3) reset。

移動時，因果視覺尺度不作為每幀的硬式 scale input；map Sim(3) registration 可共同估 pose 和 scale，候選只有在 registration gate 與後續 NIS 均接受後才進入狀態。靜止判定成立且 3D 支持可靠時，會使用當前／過去特徵間的 causal scale input 並固定此幀 registration scale。registration 或 NIS 拒絕時，候選 pose、候選 scale、bias、covariance 均不注入；輸出已做過 IMU prediction 的狀態。scale 沒有加入 EKF state。歷史 pose 不回寫。registration 以 prior 初始化，兩者可能相關；本版是近似 loose coupling，NIS 不是獨立的精度校正或外參正確性證明。此版 scale 狀態如何依 motion mode 改變，見 doc55。

## 未校正參數的意義

| 參數 | 預設 | 依據與界限 |
| --- | --- | --- |
| `T_ply_imu` | `IMU_RPY_DEG=(1,6,0)`；`IMU_XYZ_M=(0,0,0)` | 使用者指定的測試外參；尚非完整外參標定 |
| `gravity_map_mps2` | `[0,0,-9.80665]` | map +Z up 假設 |
| `registration_std` | translation 0.5 m、rotation 5° | 明示的工程模型，沒有獨立 covariance 標定 |
| `accel_noise_density` | 0.2 m/s²/√Hz | 連續白雜訊 density，不是單筆 variance |
| `gyro_noise_density` | 0.02 rad/s/√Hz | 同上 |
| accel／gyro bias random walk | 0.01／0.001 | bias 單位/√s 的擴散 density |
| `max_integration_step_s` | 0.01 s | 數值步長限制，不改資料時間 |
| `max_sample_age_s` | 0.1 s | 缺資料停止界限，不是同步精度保證 |

noise/std 是明示但未校正的 engineering priors，並非 bag 提供，也未依 Kaggle 調整。它們為未知 covariance 建立非零模型，目前不能推得正確信賴區間。外參對照先固定這些參數，避免同時調 covariance 掩蓋錯軸。長時間無地圖量測仍會 IMU drift。

## 使用者手動逐次測試外參

基準和每一組假設使用同一段資料，直接執行 `./scripts/run.sh --max-frames 30`。30 幀約一秒，只適合檢查 I/O 與短時預測；判斷 yaw 或 lever arm 需要含轉向或加減速的較長 prefix。

短段結束後，可用該 run 的 `source/scripts/analyze_imu.py` 產生唯讀診斷圖，存於 `analysis/imu/`；成功 full 會自動產生。圖表排除第一筆 bootstrap 殘差；合法 registration candidate 即使被配準 gate 拒絕，仍保存原始殘差，NIS 則只在 registration gate 通過後計算。圖表只讀 run 輸出，不重估 pose。

調整順序：

1. **先固定時鐘。**檢查 sample age、bag arrival/header 關係、stale 與 frame。PLY/bag clock 是 availability，camera/IMU headers 是 acquisition 時間；兩條件需同時通過。v5 不提供任意時間平移；修改 clock 需要延遲證據及相應 arrival 因果處理，不能用 timestamp 調整代替外參。細節見 doc55。
2. **roll/pitch 與軸向。**依安裝方向、低動態區間的 specific force 和可信 registration 姿態檢查重力投影。動態 acceleration 不能全當重力，道路傾斜也不能全當 sensor 傾角。不要任意翻轉單軸造成 det(R)=−1。
3. **yaw。**重力無法決定 IMU→camera yaw；需要轉向、有方向的運動與安裝線索。對照 `pose_trace.jsonl` 的 raw registration 和 prior，檢查旋轉殘差是否隨轉向規律變化。它們仍非 ground truth；少轉向段無法可靠校 yaw。
4. **xyz lever arm。**旋轉假設穩定後，優先用實際安裝尺寸。直線等速對平移外參不敏感，轉向才較易看出不同原點的效應；不能只靠較小 XY 殘差唯一解三維平移。
5. **一次只改一個有依據的量。**固定 frame、其餘外參、noise、gate、尺度與配準參數。比較 innovation 各軸的方向／時間結構、NIS 拒絕、bias 趨勢、速度、不確定度及連續無 map 更新。接受率、殘差或平滑不能單獨證明精度。保留失敗與假設，不做盲目網格搜尋或榜分反推。

外參在 [track3/imu_parameters.py](../track3/imu_parameters.py) 最上方直接修改：`IMU_RPY_DEG=(roll,pitch,yaw)` 是 IMU→PLY 的固定軸 XYZ 角度（度）；`IMU_XYZ_M=(x,y,z)` 是 IMU 原點在 PLY FLU 的位置（公尺）。零值是假設同向同原點，不是校正值。

每次只改一項有依據的候選，其他參數和幀數保持一致。外參程式和實際矩陣會隨 run 保存。改程式前等 full 結束。

可由使用者直接啟動 full：

```bash
./scripts/run.sh --full
```

成功 full 照常產生 `analysis/01_trajectory`、`02_pose_changes`、`03_registration_timing`（PNG/PDF）與完整 memory 圖；標準圖成功後自動增加 `analysis/imu/`。標準圖失敗記 `analysis_status.json`，IMU 圖失敗另記 `imu_analysis_status.json`，保留定位成功狀態。人工重試使用該 run 的 `source/scripts/analyze_run.py` 或 `analyze_imu.py`。Kaggle/E3 由使用者操作。
