## 直接開啟

在 **Ubuntu 桌面的主機終端**執行；第一次若尚未建置回放 executable，入口會呼叫 GPU Release 建置。

```bash
cd /home/ricky/sdc_ros2/midterm01_gpu

# 已評分前相機最佳；選一條執行，關閉後再開下一條。
python3 scripts/replay.py --track 1
python3 scripts/replay.py --track 2
```

省略 `--run` 固定選用 [17｜已評分前相機最佳](17_GEOMETRY_RESULTS_20261017.md) 的兩個原始 run，**不是依目錄時間猜最新結果**。回放入口會顯示實際來源路徑。

開啟已完成的三相機結果：

```bash
python3 scripts/replay.py --track 1 \
  --run outputs/run/track00_full_2610181301

python3 scripts/replay.py --track 2 \
  --run outputs/run/track00_full_2610181301
```

三相機入口循 `trackN/localization.json` 找到含完整矩陣的定位 run，不會拿 `result_N.csv` 補猜 Z／roll／pitch。也可直接指定含 `params.json`、`frames.csv`、`result.txt` 的任意 GPU 定位 run。兩條 Track 的地圖各自獨立，不能把它們當成同一個連續地圖。

想先停住觀察或選一段：

```bash
python3 scripts/replay.py --track 1 --paused
python3 scripts/replay.py --track 1 --start-frame 1500 --frames 100 --speed 0.5
```

`--start-frame` 是**該定位 run 內的 0-based 索引**。對於原本從中段定位的 run，原序列索引由來源 manifest 保留；HUD／CSV 同時顯示 `idx` 與 `original_idx`。`--frames 0` 表示從起點播到結尾，這與 benchmark 的幀數介面不同。

## 操作與畫面

鍵盤操作需把焦點放在**啟動回放的終端**，RViz 視窗內的滑鼠用於調整視角。

| 按鍵／選項 | 功能 |
| --- | --- |
| 空白鍵或 `p` | 播放／暫停 |
| `n`／`b` | 暫停並切到下一幀／上一幀 |
| `+`／`-` | 加倍／減半速度 |
| `r` | 暫停並回到所選片段第一幀 |
| `q` 或 Ctrl-C | 結束回放並清除本次 RViz 容器與 Xauthority cookie |
| `--loop` | 播到尾端後循環 |
| `--exit-at-end` | 播完直接結束；預設保留最後一幀並持續發布，方便查看 |
| `--headless` | 只發布 ROS 訊息，不開 RViz |

速度依原始整數 timestamp 的差值排程，不依當初配準耗時。每幀仍須讀 PLY、下採樣及裁切地圖；負載過高時會變慢，工具不跳幀追趕。回放期間可以透過另一個終端的 ROS parameter 跳幀，例如回放在 GPU 容器內的 `--headless` 模式：

```bash
docker exec sdc_midterm01_gpu bash -c \
  'source /opt/ros/humble/setup.bash && ros2 param set /localization_replay paused true'
docker exec sdc_midterm01_gpu bash -c \
  'source /opt/ros/humble/setup.bash && ros2 param set /localization_replay frame_index 20'
```

`frame_index` 是**所選回放片段內**的 0-based 索引。GUI 模式的 node 位於終端印出的 `sdc_midterm01_replay_rviz_<PID>` 容器；需要使用上述 ROS CLI 時，把容器名換成該名稱。

預設畫面：

- 灰色 LiDAR 局部地圖、原來源 RGB 點雲、綠色累積軌跡。
- Source 完整三維姿態的 XYZ 軸：X 紅、Y 綠、Z 藍。
- 黃色箭頭：source +X 在 map XY 平面的 yaw 朝向。
- 文字：幀索引、精確 `timestamp_ns`、map 中 XYZ（m）、roll／pitch／yaw（deg）、暫停狀態與速度。

RViz 設定檔為 `workspace/src/localization/config/replay.rviz`。`Fixed Frame=map`，預設視角以 `replay_source` 為觀察中心。這樣地圖座標固定，視角跟隨當幀位置；可以使用 RViz Orbit／Focus Camera 調整視角。

## 座標與朝向契約

原始矩陣按列保存為：

```text
R00 R01 R02 tx R10 R11 R12 ty R20 R21 R22 tz
```

回放沿用原程式：

```text
p_map = R_map_source × (原 run 的 ply_scale × p_raw) + t_map_source
TF: map → replay_source
R = Rz(yaw) Ry(pitch) Rx(roll)
yaw = atan2(R10, R00)；從 map +X 朝 map +Y 的正向旋轉
```

2026-10-19 播放修正：`/replay/source` 的 XYZ 現在已由回放端套用該幀保存的完整 pose，訊息 frame 為 **map**；RViz 不再等待動態 `replay_source → map` TF 才能顯示點雲。TF 仍代表 source pose，供座標軸與視角追蹤使用。這沒有改變保存的 pose／尺度，也不額外平移點雲高度。原因與連續播放測試見 [31｜播放與高度診斷](31_REPLAY_PLAYBACK_AND_HEIGHT_20261019.md)。

僅縮放點雲一次，平移不乘尺度。採用原 run 的 input voxel 與 map voxel leaf；不重新乘 init_guess、相機外參、FLU／optical 軸轉換或三相機 depth scale。三相機重建 PLY 已完成其自身的 depth／rig／同步處理，這裡依其定位 run 的 `ply_scale=1` 回放。

XYZ 和朝向屬於**已保存 source 原點在 map 中的 pose**。目前官方車體原點與完整 frame 契約仍待確認，因此畫面不宣稱它是精確車體中心，也不把 map +X／+Y 標成已確認的東／北方向。Quaternion 保留完整 3D 旋轉；RPY 用於閱讀，接近 pitch ±90° 時 Euler angles 不是唯一表示。

為了讓暫停、倒退和循環後的 TF 仍可用，ROS 訊息每次發布共用**目前回放系統時間**；原始擷取時間另完整保存在 manifest、座標 CSV 與畫面文字。工具沒有改寫原始 timestamp，也沒有使用 `/clock`。倒退／跳幀會依所選片段重建截至當幀的 path，不保留未來軌跡或重複追加。

## GUI、來源核對與回放產物

主機入口先核對所有 pose／frame 列數、有限值、正交旋轉、Track、嚴格遞增整數時間與檔名，再核對所選 PLY。新 run 若有 `source_input.json`，也核對來源尺度與原始 SHA256；較早的前相機 run 沒有逐 PLY 歷史 hash，工具只保存本次讀取 hash，不能因此宣稱已驗證其歷史檔案身分。遺失／不完整輸出會報錯，不補猜姿態。

既有 map cache 僅在 sidecar 的 Track、原始 map SHA256 與原 run 的 leaf 全部吻合時才用於**顯示**，終端與 `replay.json` 明確記錄所用 cache 及其本次 hash。找不到吻合快取就讀原始 PCD；大型 ASCII 地圖的首次讀取可能較久。回放不建立／覆寫 map cache，不修改保存的定位結果。

GUI 使用同映像的獨立暫存容器；RViz 與回放 publisher 放在同一容器，避免不同容器的 Fast DDS shared memory 不相通。沿用 GPU 掛載，但 workspace／data／outputs 對該視窗容器均為唯讀。主機只另寫本次唯一 `outputs/run/replay_YYMMDDHHmm[_N]/`：

| 檔案 | 內容 |
| --- | --- |
| `poses.csv` | idx、original_idx、整數 timestamp、XYZ 公尺、quaternion xyzw、RPY 弧度及角度；不是提交 CSV |
| `frames.tsv` | 經核對的來源檔與原始 3×4 pose，供 C++ 回放讀取 |
| `replay.json` | 來源 run、尺度／濾波、map／來源／輸出 hash 與座標契約 |
| `params.yaml`、`command.json` | 本次回放設定與啟動命令 |
| `execution.json`、`replay_sources/`、`worktree.patch` | 映像／回放 binary SHA256、回放程式快照與相關未提交差異；commit／工具 hash 記於 replay.json |
| `rviz.log` | 結束時保存的 GUI log |

需從登入 Ubuntu 桌面的終端啟動，以取得 `DISPLAY` 和目前使用者的 Xauthority。入口只分享當前 display 的 cookie，結束後刪除；不執行 `xhost +`，不修改原 GPU Compose GUI 設定，也不啟停 CPU project。RViz 使用 software OpenGL，回放不執行 CUDA 配準。主機非桌面環境可用 `--headless`。

純讀取檢查與只輸出座標：

```bash
python3 scripts/replay.py --track 1 --check-only
python3 scripts/replay.py --track 1 --frames 10 --prepare-only
```
