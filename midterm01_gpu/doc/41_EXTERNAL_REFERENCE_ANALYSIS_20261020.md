## 2. 至少約 0.319 分必須來自位置

依本機保存的官方公式，令 `S=P+0.2R`，其中 P 為平移 RMSE（m），R 為 yaw RMSE（°）。在相同真值、idx 與此可分離評分方式下，RMSE 的反三角不等式給出：

```text
|R_ours − R_external| ≤ RMS(wrap(yaw_ours − yaw_external))
                    = 0.8807766°

航向項所能解釋的最大降分 = 0.2 × 0.8807766 = 0.1761553
實際降分               = 1.15008 − 0.65479 = 0.49529
位置 RMSE 改善至少      = 0.49529 − 0.1761553 = 0.3191347 m
```

位置改善量的同一界限為 **0.31913～0.67145 m**。這不需要把外部 CSV 當真值，但依賴上述官方公式適用於目前 CSV 的 XY／yaw 評分；尚未取得完整評分程式。可確定的是，**只修 yaw 不足以解釋這次全部改善**。

使用者說明中的「航向 RMSE 0.63°」若確實是對相同真值及評分定義算出，則外部平移 RMSE 是 `0.65479−0.2×0.63=0.52879 m`。配合兩版 yaw 差，可推出本機平移 RMSE 約落在 **0.84792～1.09992 m**。這是附帶假設的推算，不能寫成已量到的真值分量；目前沒有對應真值或分項評分報告。

## 3. CSV 支持慢變修正與兩端航向差，但不能還原原算法

外部與本機的位置差平均只有 `[+0.13138,+0.02152] m`，扣掉此常數後 RMS 仍有 **0.93528 m**。連最佳全域 SE(2) 平移／旋轉擬合後仍有 **0.92325 m**。因此這份差距主要不能用一個固定 offset 或固定座標旋轉解釋；該擬合只作診斷，未套到任何提交。

把外部減本機的 XY 差做固定 12 s、置中逐座標中位數，慢變部分 RMS 為 **0.79749 m**，剩餘部分為 **0.49097 m**。中位數是非線性濾波，這兩個 RMS 不能相加或當作正交能量比例。結果支持有相當大的慢變位置差，**不能證明外部實作就是這個濾波器，也不能直接認定整段差值都是 GNSS bias**。

| --- | --- |
| 前 12 s | **1.57704°** |
| 中間（12 s 至末幀前 12 s） | **0.38337°** |

我們已經用 course 修正過原始 IMU 約 3.5–5° 的偏差，不能把原始 IMU 偏差全算成兩個最終方法的差距。實際輸出顯示差距較集中在首尾。現有 bias_rts 在觀測支持外延用邊界 mean，不外推 drift；起步／低速缺少 course 的區段因此值得優先改善，但外部 CSV 本身不能證明其 yaw 在每一幀都更準。

對各自輸出位置求行進方向，使用均勻 0.02 s 重取樣後的 Savitzky–Golay 導數，僅比較 >5 m/s 且排除首尾各 2 s：

| --- | --- | --- |

2 s 時垂直車頭方向的速度 RMS 為 **0.36553→0.08103 m/s**。這與使用 NHC／聯合估計的說明相容；若算法強制這種一致性，該指標也會自然變好，所以不能用它獨立認證定位精度。兩個來源各自用速度門檻，合格樣本數有小幅差異，詳見 `comparison.json`。

## 4. 使用者提供的方法說明及其意義

以下算法／數字來自使用者文字描述，沒有對應執行紀錄可獨立核對：

| 模組 | 外部說明 | 對本專案的啟示 |
| --- | --- | --- |
| 尺度 | 用地圖逐幀估 scale 約 8.7，沿路 7.6～9.4 | 尺度應是待估 nuisance，而非只換一個共用倍率；必須檢查 scale 與高度／姿態的耦合 |
| 配準 | 每幀獨立 6-DOF point-to-plane，地面／非地面分層對應，可用約 78% | 需能產生未被同一 GNSS 先驗拉回的 map observation，並補上來源 tilt／scale 一致性；6-DOF 本身不保證更準 |
| 可信度 | 相鄰 map 位移與 GNSS 位移一致性 | 可排除突跳；固定錯位與成群共同錯誤仍可能通過，不能只用此條件認證絕對位置 |
| 整段估計 | GNSS 位置加慢變 bias；raw gyro、NHC、加速度平滑、穩健 map factors | 現有純 GNSS 平滑不會消除慢變絕對偏差；需要獨立 map 錨點才可辨識 |
| D 版 | 用約 12 s 穩健中位數只取 map 相對 GNSS 的慢修正，優於 C4 | 合理假說是高頻 map 內容較不可靠；沒有 C4／D 配對輸出，不能自行證實因果 |
| 航向 | raw gyro 提供相對形狀，camera map yaw 定絕對值 | 需估 gyro bias，核對角速度軸／時間；原始 gyro 本身不代表零延遲、無偏或絕對航向 |

本機 raw Track1 IMU 約 110 s 的角速度，依同軸假設及 roll／pitch 換算 Euler yaw-rate 後積分，與 quaternion yaw 的總變化相差 **−29.16°**（平均有效差約 −0.265°/s，見 `gyro_consistency.json`）。這不是量到的真實 gyro bias，卻足以說明不能直接無偏差狀態地積分後當可靠 yaw；沒有把這個差值扣回 production。

尺度放大不會憑空新增牆或桿子，而是改變既有點到相機的公尺距離及其與 map 的對應範圍。地面平面多會使 XY／yaw 缺乏支持，但斜面、平面邊界及多方向結構的資訊不同；本機資料顯示最強方向幾乎為 Z，支持瓶頸判斷，不能概括成所有路面都完全沒有水平資訊。

逐幀同時估尺度與 6-DOF 時，單一平面可用高度／tilt／scale 相互補償而取得小殘差。需要分散的非地面結構、尺度邊界／可觀測性診斷及不參與擬合的空間區域，避免把錯誤尺度與深度形變解釋成正確 pose。不能將外部 8.7 直接當作本機校準值。

## 5. 後續算法修改順序

下一條主線是**由地圖提供有支持的慢變水平修正**。先保留目前最佳作對照，不再重跑已失敗的 pose_yaw／固定尺度組合。

1. 實作獨立的 map scale＋6-DOF registration，保存逐幀 scale／pose／地面與非地面支持，使用分層對應、分散取樣及多尺度搜尋。初值可用 GNSS／IMU，但不能把帶強 GNSS 正則的 posterior 再冒充獨立 map 量測。
2. 對 map−GNSS 修正先建保守慢變估計；時間一致性配合空間留出、非地面支持與穩健有界影響，避免一群錯誤對應支配整段。12 s 是外部方法的待驗證假說，需保存物理時間及端點處理，不直接當最佳參數。
3. 在 batch graph 接入 `z_gnss=p+b_gnss+noise`、可靠 map 因子、raw gyro 的相對轉向與 bias、軟性 NHC／運動平滑。無絕對 map 錨點時，`p+c,b_gnss−c` 仍有等價解；增加 bias 狀態本身不能校正位置。

先前 kinematic prototype 沒有可靠 map 錨點，也沒有 GNSS bias 狀態，所以其 noisy-GNSS 留段退步，不能據此否定這條有 map 錨點的新模型。反過來，預測 noisy GNSS 更準也不代表去掉了其絕對偏差。

這些是下一階段設計，**本輪尚未新增上述定位 solver**。不以外部 CSV 的位置／航向當訓練目標或校準值。新主流程完成機制及必要短測後，直接提供 full 指令由使用者評分，不另設本地精度勝出的資格門檻。

  --reference outputs/track1_test.csv --reference-score 0.65479 \
