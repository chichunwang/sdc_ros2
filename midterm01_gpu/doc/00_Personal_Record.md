# 學習順序

可以。我前面直接跳到「修改初值、測試配準」，省略了中間需要理解的步驟。

我們把學習順序縮小成：**先手算 → 寫成十幾行 Python → 改一個數字 → 解釋結果。** 今天先用五個一維點，只估計左右平移，讓每一步都能看清楚。

**第一步：先理解我們要找什麼**

拿紙寫下兩組點：

```text
地圖：  0、 1、2、3、4
來源： -2、-1、0、1、2
```

來源整體往右移 **2**，就會與地圖重合。因此這個人造例子的正確答案是：

```text
平移量 t = 2
```

這裡有已知答案，方便你檢查程式。

**第二步：手算一輪 ICP**

先假設我們猜的位置是：

```text
t = 1.8
```

ICP 一輪做三件事：移動來源、找最近點、算修正量。

| 來源點 | 加上目前 t＝1.8 | 地圖最近點 | 還需要移動多少 |
|---:|---:|---:|---:|
| −2 | −0.2 | 0 | +0.2 |
| −1 | 0.8 | 1 | +0.2 |
| 0 | 1.8 | 2 | +0.2 |
| 1 | 2.8 | 3 | +0.2 |
| 2 | 3.8 | 4 | +0.2 |

把最後一欄取平均：

```text
修正量 = 0.2
新的 t = 1.8 + 0.2 = 2.0
```

再做一輪，每個點都已經對齊，修正量就是零，程式可以停止。

你現在已經手算過一次最簡單的 ICP。

**第三步：把剛才的動作翻成 Python**

在 VS Code 新增：

`midterm01_gpu/scripts/learn_icp_1d.py`

建議你逐行輸入，每輸入一段，都對照剛才的表格：

```python
map_points = [0.0, 1.0, 2.0, 3.0, 4.0]
source_points = [-2.0, -1.0, 0.0, 1.0, 2.0]

t = 1.8

for iteration in range(10):
    moved_points = [p + t for p in source_points]

    corrections = []

    for p in moved_points:
        nearest = min(map_points, key=lambda q: abs(q - p))
        corrections.append(nearest - p)

    delta = sum(corrections) / len(corrections)
    t = t + delta

    print(f"第 {iteration + 1} 輪：修正 {delta:.6f}，t = {t:.6f}")

    if abs(delta) < 0.000001:
        break
```

幾個容易卡住的地方：

- `[p + t for p in source_points]`：每個來源點都加上平移量。
- `min(..., key=lambda q: abs(q - p))`：從地圖中，挑出與目前這個 `p` 距離最小的點。
- `nearest - p`：這個點還需要移動多少。
- `sum(...) / len(...)`：把所有點的修正量取平均。
- `break`：修正已經很小，結束反覆計算。

這是五個數的主機 Python 練習，可以直接執行一條命令：

```bash
python3 /home/ricky/sdc_ros2/midterm01_gpu/scripts/learn_icp_1d.py
```

預期結果約為：

```text
第 1 輪：修正 0.200000，t = 2.000000
第 2 輪：修正 0.000000，t = 2.000000
```

**第四步：開始你自己的初值實驗**

現在只修改這一行，其他程式保持相同：

```python
t = 1.8
```

依序試三個初值，自己記錄：

| 初始 t | 最後得到的 t | 與正確答案 2 的差距 |
|---:|---:|---:|
| 1.8 | 自己填 | 自己填 |
| 3.0 | 自己填 | 自己填 |
| 0.0 | 自己填 | 自己填 |

**每次執行前，先猜結果。** 執行後再看自己的預測哪裡不對。

你會發現，初始值為 `3.0` 時，最後會停在約 `2.8`。可以手算它：

```text
移動後：  0.8、1.8、2.8、3.8、4.8
最近點：  1、  2、  3、  4、  4
修正量： +0.2、+0.2、+0.2、+0.2、-0.8
```

修正量平均為零，所以程式停止了，但答案仍然錯了。原因是**最近點對應已經配錯，而且這組錯誤對應讓平均修正互相抵消**。

這就是你要親手理解的第一個核心現象：

> ICP 停止更新，只表示目前的配對與修正達到穩定；它可能穩定在錯誤的位置。

先把這個小實驗做到「能手算一輪、看懂每行程式、解釋三次結果」。接著增加二維平移，再增加旋轉，最後才接真實點雲；每次只增加一個需要理解的東西。

# 專案基本解析和困難點
對，**LiDAR 建立的地圖是我們的幾何參考**。更精確地說，它提供一個固定的 `map` 座標系；我們要估計每一幀相機在這張地圖裡的**位置與朝向**。

做法是把相機點雲縮放、旋轉、平移：

$$
p_{\text{map}}=R\,(s\,p_{\text{camera}})+t
$$

其中 `s` 是尺度、`R` 是旋轉、`t` 是位置。希望轉換後，同一面牆、同一段路緣能落到 LiDAR 地圖中的對應結構上。

困難主要有以下幾個：

| 困難 | 實際意思 |
|---|---|
| **相機重建的形狀不完全正確** | LiDAR 直接量距離；相機重建的深度可能有尺度偏差，甚至近處、遠處的誤差比例不同。只乘一個倍率，未必能把整片點雲修正好。 |
| **不知道哪些點互相對應** | 相機中的某個牆面點，究竟對應地圖哪一面牆？ICP 常用最近點開始猜；初始位置或尺度錯太多，就容易配到錯的結構。 |
| **有些結構無法決定所有方向** | 一大片平坦路面可以限制高度、roll、pitch，但沿路面前後或左右滑動，仍然很貼合，因此很難靠它決定 XY、yaw。 |
| **兩份點雲看到的東西不同** | 相機視野有限，地圖可能涵蓋四周；遮擋、車輛、行人及不同時間的場景變化，也會造成無法對應的點。 |
| **不同錯誤會互相掩蓋** | 尺度錯了，有時可以靠改高度、傾斜或位置，讓部分點看起來很貼。因此「殘差很小」不一定表示位置正確。 |

**我們目前最明顯的瓶頸，是相機點雲提供的水平定位約束太弱。**

想像把一張只畫著平坦地板的透明紙，疊到另一張地板上：上下高度容易對齊，但透明紙沿地板滑動一公尺，仍然看起來對得很好。加入牆角、路緣、柱子等不同方向的結構後，才能限制這些滑動。

所以 GNSS／IMU 的用途，是先告訴我們「大概在哪裡、朝哪裡」，幫助找到正確對應；接著應由可靠的地圖結構修正它。**我們現在地圖只修了約 1.6 cm，最後的位置仍主要跟著 GNSS，這就是目前改善幅度有限的原因。**

另外，點雲對齊後得到的是相機來源座標系在地圖中的 pose；若提交要求的是車體參考點，還需要確認相機到車體的外參，才能正確轉換。

# Track3 IMU Kalmal filter
可以。用你熟悉的剛體運動來理解：**先依運動方程預測，再用帶有誤差的量測修正；同時估計「自己可能錯多少」。**

這次的兩個資訊來源是：

- **IMU 陀螺儀**：量到角速度，告訴我們短時間內轉了多少。
- **點雲與地圖配對**：提供當前位置、方向的另一個估計，但它也可能配錯。

先只考慮平面轉向，就能把原理弄清楚。

**1. 先寫出你要估什麼**

先估兩個物理量：

$$
\psi=\text{平面朝向角},\qquad
b=\text{陀螺儀的固定偏差}
$$

例如，車沒有轉動，陀螺儀卻一直讀到 \(0.1^\circ/s\)，積分 100 秒就會憑空多出 \(10^\circ\)。所以需要辨識並扣除這個偏差。

**2. 每收到一筆 IMU，就用運動學往前算**

$$
\boxed{
\psi_{\text{預測}}
=
\psi_{\text{上次}}
+
(\omega_{\text{IMU}}-b)\Delta t
}
$$

就是角速度積分。

兩張影像之間若收到好幾筆 IMU，就依各筆的時間間隔逐次累加。只能使用當時已收到的量測。

**3. 預測角度之外，也記錄它的不確定度**

先暫時把 \(b\) 當作已知，讓問題簡單一點：

$$
P_{\text{預測}}=P_{\text{上次}}+q
$$

這裡：

- \(P=\sigma^2\)：角度估計誤差的變異數，單位是「度平方」。
- \(q\)：這段時間因陀螺儀噪聲、運動近似而增加的不確定度。

距離上次可靠校正越久，通常越不確定自己的方向。

**4. 點雲配到地圖後，先判斷這次量測是否合理**

它會給出另一個方向估計 \(\psi_{\text{地圖}}\)。

先比較：

$$
e=\psi_{\text{地圖}}-\psi_{\text{預測}}
$$

例如，IMU 顯示這 36 ms 幾乎沒轉，地圖配準卻說轉了 \(170^\circ\)，這筆地圖觀測就應先被排除。

**這是融合前的一致性檢查。** 被拒絕時，保留這一刻的運動預測。

**5. 合理的量測，再依可信程度修正**

單一角度下，Kalman 的計算很簡單：

$$
K=\frac{P_{\text{預測}}}{P_{\text{預測}}+r}
$$

$$
\boxed{
\psi_{\text{更新}}
=
\psi_{\text{預測}}
+
K(\psi_{\text{地圖}}-\psi_{\text{預測}})
}
$$

其中 \(r=\sigma_{\text{地圖}}^2\)，代表地圖方向觀測的不確定度。

- 地圖觀測比較可靠，\(K\) 較大，修正比較多。
- 運動預測比較可靠，\(K\) 較小，修正比較少。

最後更新不確定度：

$$
P_{\text{更新}}=(1-K)P_{\text{預測}}
$$

再拿這個結果進入下一個時間點。這就是反覆的「預測—校正」。[更新式參考](https://www.mathworks.com/help/control/ug/kalman-filtering.html)

你可以把加權修正想成：**兩根扭轉彈簧，分別把同一個旋轉塊拉向兩個估計角度。較可信的一邊，相當於彈簧比較硬，最後角度就靠近它。** 這是數學上的類比。

下面是合成教學例子；調大其中一邊的誤差尺度，看看合併角度往哪邊靠。

你親自做的話，我建議從這個小實驗開始，先用紙筆算一次，再用 Python 重複計算：

1. **自己設定一個知道答案的轉動。** 假設以 \(5^\circ/s\) 轉動 20 秒，所以真實角度是 \(\psi(t)=5t\)。
2. **模擬有誤差的陀螺儀。** 讓它讀到 \(5.1^\circ/s\)，再加入少量隨機噪聲。先只積分，觀察角度如何漂移。
3. **每秒提供一次帶噪聲的角度觀測。** 用它模擬地圖配準，依上面的公式逐次校正。每一步記錄時間、預測角度、\(P\)、觀測角度、\(K\)、更新角度。
4. **再把偏差 \(b\) 也當成未知量一起估。** 如果預測反覆轉過頭，而可靠觀測持續顯示轉得比較少，濾波器便能逐步辨識陀螺儀偏差。
5. **最後才加入位置、速度與尺度。** 位置先用 \(x_{\text{預測}}=x+v_x\Delta t\) 等運動學關係，再由連續的位置觀測修正速度。

這次實際程式有一個重要界限：**陀螺儀只能幫忙估轉動，不能單靠它知道車前進了幾公尺。** 起始速度目前設為零，需要連續可信的地圖位置觀測，才逐步建立速度估計。我們也還沒有把加速度積分成位置。

你的第一張練習圖，畫出「自己設定的真實角度、單純 gyro 積分、帶噪聲的角度觀測、Kalman 估計」四條線，就能直接判斷它究竟修正了什麼。
