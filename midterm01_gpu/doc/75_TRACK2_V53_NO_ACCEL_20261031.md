# Track2 v5.3 no-accel：保留算法、移除效能改動

> **歷史對照已結束：**live 已恢復為 `track2_causal_time_reference_likelihood_v5_3`，Track2 perf1 路徑已加回；本文件的 no-accel 版本不再是現行入口。v5.3 + perf1 的 full `track02_full_2610311612` 使用者回報 Public Score 為 `0.80300`。五個 generated scenes 與既有真實前五幀 A/B 均未顯示加速版輸出差異，不能因此認定完整 full 相同，也沒有證據顯示移除加速能修正分數。恢復所用的 source SHA 收據、no-accel 範圍稽核與生成輸出仍保留在本文連結的歷史 run；完整 regression analysis 見 [doc76](76_TRACK2_V53_REGRESSION_AUDIT_20261031.md)。目前不建議原樣重跑同一 v5.3 + perf1 full 期待改善分數。

## 當時狀態與操作（歷史紀錄）

當時 live 版本是 `track2_causal_time_reference_likelihood_v5_3_no_accel`，已比對並套用 7 個檔案的 SHA，套用時沒有活動中的定位程序。Track2 perf1 效能路徑已移除，v5.3 因果定位算法保留；CUDA 計算仍使用原 GPU 路徑，沒有切換成 CPU fallback。以下保留當時的手動命令，現況以本文頂端提示為準：

```bash
cd /home/ricky/sdc_ros2/midterm01_gpu
./scripts/run_track2.sh --full
```

## 為什麼建立這個版本

使用者回報 v5.3 加上 `v5_2_perf1` 效能改動後的 full `track02_full_2610311612` 得到 Kaggle Public Score `0.80300`。該 run 已完成 3299 幀，記錄的來源 SHA 與當時 live source 一致。這是使用者回報的分數，不是逐幀真值。

這個結果和舊 v5.2 的 `0.46434` 來自不同算法版本。v5.3 同時包含 GNSS 航向、參考點重定錨與 map-only likelihood 等算法變更；目前不能把分數差異歸因於 perf1 加速。新版本的目的，是保留 v5.3 算法、撤掉 Track2 的 perf1 執行路徑，提供可比較的對照版本。這不保證分數會變低或回到舊分數；即使生成資料數值相同，也不能證明兩次 full 會完全相同。

## 保留與移除的內容

v5.3 的因果 GNSS prior、可觀測性處理與 correction-memory 演算法保留原樣；`causal_prior.py`、`observability.py`、`correction_filter.py` 不變。Track2 的 GNSS bias、likelihood、NIS／motion／step／quality gates、solver 迭代次數與參數也維持 v5.3 設定。這次不改參數來追逐 Public Score。

| 範圍 | no-accel 版本的處理 | 注意事項 |
| --- | --- | --- |
| `camera.py` | 恢復至 `track02_full_2610311445` 所用的 pre-perf 實作，包含遮罩點雲的 host roundtrip | 移除 perf1 的 GPU 遮罩路徑 |
| `visualization.py` | 恢復至 pre-perf 逐點轉換實作 | 移除 perf1 的 CUDA RViz 點轉換 |
| `metric_registration.py` | `evaluate` 使用完整 pre-perf 計算路徑，每次呼叫保留完整 Jacobian 與診斷；同時保留 v5.3 map likelihood 所需的 `data_g` | 不再使用 `diagnostics=False` 的精簡路徑；v5.3 likelihood 算法仍在 |
| `run_track2.py` | 恢復原有遮罩 host roundtrip、RViz 轉換及 timing 欄位；移除 perf1 新增的 phase profile | 保留 v5.3 的 camera-header stamp 與 trace camera timestamp |
| Track3 共用 helper | 保留既有 `jacobian` 參數以維持相容；Track2 呼叫預設完整 Jacobian | 不改 Track1、Track3 行為或來源 |
| `parameters.py` | 僅更新 `VERSION` 識別，其餘參數不變 | solver iterations、門檻與 GNSS／filter 誤差預算不調整 |

這個版本撤掉的是上表列出的 Track2 perf1 效能路徑，不代表把 v5.3 的因果定位算法回退成 v5.2。特別是，v5.3 的 map-only likelihood 仍從完整 solver 計算中取回所需 data gradient，再只融合一次 map 資訊。

## 驗證狀態與限制

no-accel 版本已套用 live；套用前確認沒有活動中的定位，7 個檔案的來源 SHA 均受保護並記入收據，live source 與 1713 凍結快照的 SHA 相符。`track00_test_2610311713` 的生成檢查為 **78 passed、0 failed，15.324 秒**；五個 generated scenes 的 pose、scale、correction 差異全為 0，decision 也相同。這只說明合成場景的版本對照結果，不能保證 full 的輸出會相同。

1713 的範圍稽核確認 `causal_prior.py`、`correction_filter.py`、`observability.py` 與 Track3 共用初始化沒有被修改，`metric_registration.py` 的 v5.3 fusion block bytes 與原版一致；`camera.py`、`visualization.py` 與 pre-perf `track02_full_2610311445` 的來源 SHA 一致。測試沒有執行真實定位，no-accel 目前尚無 full 或 Public Score。v5.3 + perf1 的 full `track02_full_2610311612` 已完成 3299 幀，輸出及 SHA 原樣保留。

這是比較效能路徑是否伴隨輸出差異的 A/B 對照，不是已證明的分數修正。v5.3 + perf1 的 `0.80300` 與 v5.2 的 `0.46434` 來自不同算法版本，不能單獨說明是哪項改動造成分數差異；no-accel 版本跑完後也仍需依其自身 full 輸出與分數判讀。合成檢查通過、五個 generated scenes 數值相同、效能路徑被移除或輸出完整，都不能代替逐幀真值或精度證明。
